# Decision log

| Date | Decision | Why |
|---|---|---|
| 2026-11-01 | Unreal Engine 5.8 + C++, Blueprints only where needed (UMG layout, asset refs) | Owner's choice; C++ keeps logic testable and fast |
| 2026-11-01 | Materials use Custom (HLSL) nodes, unlit, instanced tiles | Mobile performance: one draw call for the ring |
| 2026-11-01 | Two rule sets: Doubling (Classic, v1) and Addition (later mode) | Owner chose "both as modes" |
| 2026-11-01 | v1 = Classic only | Ship small, then iterate |
| 2026-11-01 | Ads via an opt-in "Support" page (banner / no ads / tip) | Keep the game soothing; the defaults are still open (see MONETIZATION.md) |
| 2026-11-01 | Rules in a pure C++ `Core/` layer with headless automation tests | Verification without manual play; cheap iteration |
| 2026-11-01 | Package name `com.doubleit.game` (placeholder) | Must be finalised before the first Play upload |
| 2026-11-01 | Procedural digits (rounded hand-lettered strokes; first seven-segment) instead of a font atlas | No texture memory, crisp at any size; strokes were softened so the board feels hand-made, not generic |
| 2026-11-01 | Materials generated by a C++ commandlet from `.hlsl` files | Reproducible, diffable shaders; no manual node wiring |
| 2026-11-01 | Engine `Entry` map + everything spawned from C++ | No level asset to maintain for a single-screen game |
| 2026-11-01 | Prototype HUD on `AHUD` canvas | Fast to iterate; move to UMG (C++ base + WBP layout) in M2 |
| 2026-11-01 | "Dusk Lagoon" visual identity (dark-first, sea-glass tiles) | Owner wanted a look that isn't the generic beige/clay one; picked from 3 directions |
| 2026-11-01 | Sounds synthesized in C++ (`DISynth`) | No audio assets or licences; tiny APK; pitch follows chain depth |
| 2026-11-01 | UI built in C++ UMG (no WBP) | Owner choice; keeps Blueprints out, so the UI is reviewable in diffs |
| 2026-11-01 | Nunito from google/fonts (variable) + fontsource (static 400 latin) | Variable default is ExtraLight; Regular is needed for small text |
| 2026-11-01 | Theme follows the phone via a UPL Java method + JNI | No engine API for night mode |
| 2026-11-01 | Doubling chain rule `O < C ? 2C : 4O` | Keeps values on the power-of-two ladder; mirrors Atomas' "center+1 / outer+2" |
| 2026-11-01 | Ring has no fixed top: after each step it re-anchors (`DIRingLayout::Reanchor`, circular mean of piece displacement) | Owner: fusions must collapse from both sides onto the plus and gaps open evenly, not rotate clockwise |
| 2026-11-01 | Moves resolve instantly in Core, then play back in steps (land, one collision per ~220 ms, settle) | Each collision gets its own rising note, haptic and ripple; a tap mid-playback fast-forwards, so no input is lost |
| 2026-11-01 | Invisible adaptive pace (`Core/DIAdaptive`), both ways, bounded (plus 14-22%, growth every 34-50 moves), one profile per mode | Owner: learn the player, no setting; help is stronger than push because early losses drive quitting |
| 2026-11-01 | Profile survives reinstall via Android Auto Backup (`allowBackup`); Play Games cloud save and Block Store later | Auto Backup needs no sign-in or permission; shared Documents needs a folder picker on Android 11+, so not used |
| 2026-11-01 | Sea-glass pebble stones: seeded outlines that slowly morph, soft dome shading, frosted grain | Owner: an organic look, not a generic AI game; picked from 3 directions |
| 2026-11-01 | Idle breathing in the vertex shader (World Position Offset), not CPU | A still board does no CPU work and touches no instance buffers; key for battery |
| 2026-11-01 | Springs at damping ratio ~0.75 (~3% overshoot) | Owner found the first bounce (~10%) too much; asked for subtle |
| 2026-11-01 | Mobile MSAA off, `t.MaxFPS=60` | Shaders antialias their own edges, so MSAA only cost bandwidth; 60 fps is plenty for a calm puzzle and saves battery |
| 2026-11-01 | Camera moves to centre the ring between the HUD bands; zoom out only, capped on big tablets | Fixed camera overlapped the HUD on tablets and foldables; background switched to absolute world position for this |
| 2026-11-01 | Modes as Strategy (`IDIRuleSet`) + data (`FDIModeConfig`) + registry keyed by name; enum switches removed | Owner: keep logic dynamic and hard-code only what must be; a new mode is one class and one Register call |
| 2026-11-01 | Feel/layout numbers in a `UDeveloperSettings`, rule overrides in `[DoubleIt.Mode.<Key>]` INI sections | Tunable without recompiling and visible in Project Settings; Core stays UObject-free, so rule configs are plain structs |
| 2026-11-01 | Best scores keyed by mode (`Bests` map), old `BestDoubling` / `BestAddition` migrated on load | New modes need no new save fields; existing players keep their bests |
| 2026-11-01 | Event hub as a `UWorldSubsystem` with typed native delegates, not Lyra's Gameplay Message Subsystem | Single-player, a handful of listeners: compile-checked events and no plugin; the ring view stays driven directly (controller -> view) |
| 2026-11-01 | Special pieces as Type Objects (`IDIPieceType`) + one weighted spawn table | A new piece no longer touches FDIGame, layout or spawner; the table keeps the old roll order, so seeds replay identically |
| 2026-11-01 | Save `SaveVersion` (default 0) + ordered migration steps, additive changes only | Old saves have no version field and load as 0; database-style steps are the common advice for USaveGame |
| 2026-11-01 | Player text in a CSV string table via `LOCTABLE_FROMFILE_GAME`, staged NonUFS | Ready for translation in the Localization Dashboard without assets; literal path so the gatherer finds it |
| 2026-11-01 | Sound cues as data (`UDIGameSettings::Cues`) | Sounds tunable without code; events name cues, pieces name their landing cue |
| 2026-11-02 | Alive motion in the pixel shader (area-keeping squash, seeded shrug, inner sway), quads padded 1.25x | Feels like a soft creature at zero CPU cost; padding instead of shrinking keeps stone size and tap areas unchanged |
| 2026-11-02 | Notes follow a 5-tone chord progression (Cmaj9 Am9 Fmaj9 G6add9) instead of a fixed pentatonic | Same step spacing as before, but moves form a slowly changing harmony; five tones per chord keep every combination consonant |
| 2026-11-02 | Room reverb baked into each cached note; ambience as generated loops re-queued on underflow | No runtime effect chain or submix to set up on mobile; a handful of cached notes (~250 KB each) and three ~2 MB loops |
| 2026-11-02 | Soft-body deform as a log-stretch pair (2 floats) computed on the CPU only while animating | Stretch and wobble add up and keep the area; a still board still costs no CPU |
| 2026-11-02 | Status glow driven by eased fullness, bloom and game-over in the background shader | Shows how the run is going without any UI; one quad, no extra draw |
| 2026-11-02 | Save v2 adds effects/ambience volumes (-1 = unset, filled from settings by MarkNew or the 1 -> 2 step) | Defaults stay in settings, not in the save class |
| 2026-11-02 | Sea rendered live (Core/DISea, seeded waves on the audio thread) instead of a 24 s loop | A looped wash with even swells sounded like one tone on repeat; irregular waves with a swell, break and foam shape never repeat and cost a little CPU only while sound is on |
| 2026-11-02 | Run saved as an FArchive blob from Core (`FDIGame::SerializeRun`) inside the save, after every move and on background | Core stays UObject-free with one function for both ways; saving per move (a few KB) means even a sudden kill loses nothing; the blob has its own format number so a bad one is simply dropped |
| 2026-11-02 | `build_editor.ps1` passes `-DisableAdaptiveUnity` | UBT compiles edited files outside the unity blobs, so anonymous-namespace name clashes only appeared on the first build after committing (twice); now they fail before the commit |
